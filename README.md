# AI 모의 면접 코치

카메라와 마이크로 **시선·몸짓·말투·발성·안정감**을 실시간으로 분석하고, 가상 면접관 두 명이 질문·꼬리질문을 던지는 모의 면접 연습 앱입니다. 로그인 없음, 서버 없음 — 영상과 음성은 기기 안에서만 처리됩니다.

## 실행

```bash
npm install
npm run dev
```

브라우저(**Chrome 또는 Edge** 권장)에서 `http://localhost:5173` 을 엽니다. 카메라·마이크 권한을 허용하면 됩니다.

> 음성 인식(말투·내용 평가)은 브라우저 내장 Web Speech API 를 쓰므로 Chrome/Edge 에서만 동작합니다. Chrome 은 음성을 Google 인식 서버로 보냅니다. 다른 브라우저에서는 시선·자세·발성 평가만 됩니다.

배포용 빌드:

```bash
npm run build      # dist/ 생성
npm run preview    # 빌드 결과 미리보기
```

## 사용 흐름

1. **설정** — 면접관 5명 중 2명 선택(먼저 고른 쪽이 첫 질문), 질문 팩 선택 또는 직접 입력, 꼬리질문/답변시간 설정
2. **보정** (약 10초) — 배경 소음 측정 → 카메라 정면 응시 → 화면 왼쪽 끝 → 아래쪽. 시선 판정 기준을 사용자·카메라 위치에 맞춥니다.
3. **면접** — 면접관이 질문(TTS + 자막) → 답변 → 침묵이 이어지면 다음으로. 답변이 짧거나 빗나가면 되묻습니다. 오른쪽에 실시간 게이지와 경고, 받아쓰기가 표시됩니다.
4. **결과** — 총점, 5개 항목별 점수·세부 지표·개선 팁, 답변 내용 평가, 시간대별 변화, 질문별 기록. `.txt` 로 저장 가능.

## 평가 방식

| 항목 | 신호 | 방법 |
|---|---|---|
| 시선 처리 | 얼굴 랜드마크 + 안구 블렌드셰이프 | 보정값 기준 정면 응시 비율(60~93% 가 이상적 — 100% 응시는 오히려 부자연스럽다고 봄), 아래 보기, 시선 흔들림, 깜빡임 |
| 몸짓 | 포즈 랜드마크 | 어깨 기울기, 움츠림(목 비율), 상체 흔들림, 손동작 양(너무 없어도 감점), 얼굴 만지기 |
| 말투·전달 | 마이크 타이밍 + 받아쓰기 | 긴 침묵(막힘)에 가장 큰 비중, 발화 비율, 말 속도(음절/초), 간투사, 더듬음, 문장 마무리 |
| 발성 | 마이크 RMS | 배경 소음 대비 dB(SNR), 작게 말한 비율, 기복, 말끝 흐림. 전반적으로 안 들리면 상한선 적용 |
| 안정감 | 무릎/골반 y 좌표의 자기상관 | 2.5~9Hz 주기 진동 = 다리 떨기. 손 만지작거림, 깜빡임. 다리를 계속 떨면 상한선 적용 |
| 답변 내용 | 질문 키워드 매칭 + 사례/수치/구조 마커 | 개방형 질문(자기소개 등)은 키워드 비중을 낮춤. 침묵한 문항은 0점으로 평균에 포함. 선택적으로 Claude API 로 실제 이해 기반 평가 |

다리까지 카메라에 보이면 떨림 감지가 정확해집니다. 안 보이면 골반의 미세 진동으로 추정합니다.

채점 세부:
- 떨림 판정은 자기상관에서 **골 뒤에 솟는 봉우리**만 인정하고, 대역보다 느린 움직임(자세 이동·호흡·몸 흔들림)은 먼저 제거합니다. 그래서 천천히 몸을 움직이는 것은 떨림으로 잡히지 않습니다.
- 몸 흔들림·손동작 속도는 랜드마크 위치를 부드럽게 한 뒤 차분을 내므로 트래커 잡음이 "움직임"으로 둔갑하지 않습니다.
- 말투 점수에는 **답변 시작까지 걸린 시간**과 **실제 발화 비율**의 상한이 들어갑니다. 아무 말도 안 하면 끊김이 없어도 높은 점수가 나오지 않습니다.
- 각 항목의 총평은 점수만 보고 고르지 않고, 세부 지표 중 '나쁨'이 있으면 그것을 먼저 말합니다.

## 면접관을 실제 사람처럼 보이게 하기 (사진 기반 2.5D)

기본 면접관은 벡터 그림입니다. **AI로 만든 가상 인물 사진**을 넣으면 사진이 실제로 움직입니다 — 말할 때 입이 벌어지고, 눈을 깜빡이고, 끄덕이고, 메모할 때 고개를 숙입니다.

1. 설정 화면 → "실제 사람처럼 보이게 하기 — 사진 만드는 법" 을 열어 면접관별 프롬프트를 복사
2. 이미지 생성 도구(ChatGPT, Midjourney, Gemini 등)에서 사진 생성
3. 각 면접관 카드의 **사진 넣기**로 업로드

원리: 사진에서 MediaPipe 얼굴 메시(468점)를 뽑아 WebGL 로 사진을 그 메시에 입히고, 정점을 움직여 표정·고개를 만듭니다 (`src/face/`). 사진은 브라우저(localStorage)에만 저장되고 어디에도 전송되지 않습니다. `public/interviewers/{id}.jpg` 에 파일을 두면 기본 사진으로도 쓸 수 있습니다.

잘 되는 사진: 정면, 무표정, **입 다물기**, 눈 뜨기, 어깨까지 나오는 구도, 단색 배경, 1024px 이상. 입이 벌어진 사진은 말할 때 치아가 늘어나 보이고, 옆얼굴은 인식이 안 됩니다. **실존 인물 사진은 쓰지 마세요.**

## 말이 끝났는지 판단하기 (턴 감지)

침묵 길이만 보면 "숨 고르는 것"과 "답변 끝"을 구분할 수 없습니다. 그래서 받아쓰기 텍스트의 문법 상태를 함께 봅니다 (`src/interview/turn.ts`):

- "…했습니다", "…인데요" 처럼 **종결어미**로 끝남 → 기본 침묵 시간의 80% 면 넘어감
- "…했고", "그래서", "제 강점은", "어…" 처럼 **연결어미·조사·간투사**로 끝남 → 최대 7.5초까지 기다림 (자막에 "말씀이 이어질 것 같아 기다리고 있습니다" 표시)
- 인식기가 아직 interim 결과를 내는 중 → 기다림

받아쓰기가 안 되는 브라우저에서는 침묵 길이만 씁니다. `?sim=breath` 시나리오가 이 동작을 검증합니다.

## 선택: 면접관 두뇌 (AI 가 답변을 읽고 되묻기)

설정 화면의 **면접관 두뇌**에서 고릅니다. 어느 쪽이든 실패하면 조용히 규칙 기반으로 돌아가 면접은 끊기지 않습니다.

| 선택 | 비용 | 특징 |
|---|---|---|
| 없음 (규칙 기반) | 0 | 키워드·길이·사례 마커로 되물음. 기본값 |
| **Gemini — 무료** | 0 | https://aistudio.google.com/apikey 에서 카드 없이 만든 키. 하루 수백 회. 답변 텍스트가 Google 로 감 |
| Claude — 유료 | 8문항에 몇백 원 | `claude-opus-5`. 이해력이 가장 좋음 |

두뇌를 켜면: 답변을 읽고 **방금 한 말을 짚어 되묻고**, 성향에 맞으면 **옆 면접관이 이어받아** 캐묻고, 다음 질문 앞에 **연결 문장**("수요 예측 얘기 흥미롭게 들었습니다.")을 붙이며, 끝나면 리포트에 **내용 총평(잘한 점·고칠 점)**을 씁니다. 키는 브라우저 localStorage 에만 저장되고 요청은 기기에서 직접 나갑니다. 공용 PC 에서는 쓰지 마세요. "연결 테스트" 버튼으로 키를 확인할 수 있습니다.

구조: `src/interview/llm.ts`(제공자 선택) → `llmGemini.ts` / `llmClaude.ts`, 공통 프롬프트는 `llmPrompts.ts`. `?sim=llm` 은 가짜 두뇌로 이 흐름을 검증합니다.

## 개발

```bash
npm test             # 채점·신호처리·시선·떨림·턴 감지·면접관 로직 테스트 (vitest, 141개)
npm run typecheck
npm run lint
npm run render:avatars   # 아바타/면접장 장면을 .preview/*.png 로 렌더링해 눈으로 확인
```

- `?preview=report` — 카메라 없이 결과 화면 확인 (합성 데이터를 실제 채점 파이프라인에 통과)
- `?preview=interview` — 면접 화면 레이아웃 확인
- `?preview=face` — 사진 얼굴 파이프라인 확인 (업로드 → 상태 전환 → 립싱크). 개발 서버에서는 `fetch("/__snapshot")` 로 캔버스를 `.preview/` 에 PNG 저장 가능
- `?debug=1` 또는 화면에서 `Shift+D` — fps, 시선 값, 다리 떨림 주파수 등 진단 표시

### 카메라 없이 전체 면접 돌려보기 (시뮬레이션)

`http://localhost:5173/?sim=basic` 처럼 열면 카메라·마이크·MediaPipe·음성 인식이 전부 가짜로 바뀌고, 나머지 세션 로직(보정 → 질문 → 답변 판정 → 꼬리질문 → 채점 → 리포트)은 실제 코드가 그대로 돕니다. 왼쪽 아래 조종석에서 **시나리오 시작**을 누르면 보정 뒤 자동으로 면접이 진행됩니다.

- 가짜 카메라: `src/sim/synth.ts` 가 MediaPipe 정준 얼굴 메시를 회전시켜 랜드마크를 합성하고, 무릎·손목 좌표에 떨림·만지작거림을 넣습니다. 자기 화면에는 그림으로 그려집니다.
- 가짜 마이크: Web Audio 로 배경 소음(-55 dBFS)과 목소리(보통 -25 / 작게 -46 dBFS)를 합성해 진짜 `MicAnalyzer` 가 분석합니다. 면접관 TTS 가 스피커로 되돌아오는 잔향도 흉내냅니다.
- 가짜 인식기: `window.SpeechRecognition` 자리에 대본을 읽어 주는 객체를 꽂아 진짜 `Stt` 클래스(게이트, 에코 필터, 재시작)를 그대로 검증합니다.
- 시나리오(`src/sim/scenarios.ts`): `basic`(안정 → 다리 떨기·작은 목소리 → 짧은 답과 꼬리질문), `nudge`(침묵과 재촉, 시선 이탈, 얼굴 만지기), `good`(모범 답변 5문항), `breath`(문장 중간 숨 고르기 — 턴 감지), `llm`(가짜 두뇌로 이어받기·연결 문장·총평). 리포트는 `window.__simReport` 로도 읽을 수 있습니다.

이 모드로 찾아 고친 것: 느린 몸 움직임이 "10Hz 다리 떨림"으로 잡히던 문제, 답변 사이의 면접관 차례가 "긴 침묵"으로 세어지던 문제, TTS 잔향 때문에 답변을 시작하기도 전에 침묵 종료가 걸리던 문제, 말끝 흐림이 발화 판정 꼬리 때문에 부풀던 문제, 지시어 "그"가 간투사로 세어지던 문제.

### 구조

```
src/
  vision/      MediaPipe 로딩, 시선·자세·떨림 산출 (analyzer.ts)
  audio/       마이크 레벨(micAnalyzer), 음성인식(stt / sttNative), TTS(립싱크 신호 포함)
  face/        사진 얼굴: 랜드마크 리그(rig), WebGL 렌더(faceGl), 표정 애니메이터, 립싱크, 사진 저장
  scoring/     지표 누적·채점(metrics), 한국어 답변 분석(korean)
  interview/   면접관 판단(brain), Claude 연동(llm), 세션 상태 머신(useSession)
  components/  화면 (Setup / Interview / Report), 면접장 장면(InterviewRoom), 인물(Avatar)
  data/        면접관 5명(가상 인물), 질문 팩
public/mediapipe/  wasm 과 모델 파일 (오프라인 동작)
```

## 안드로이드 APK (선택)

Capacitor 로 감싸는 설정이 되어 있습니다. **Android Studio(또는 Android SDK + JDK 17)가 설치된 PC**에서:

```bash
npm run android:apk
# → android/app/build/outputs/apk/debug/app-debug.apk
```

또는 `npm run android:open` 으로 Android Studio 에서 열어 빌드합니다.

주의:
- 안드로이드 WebView 에는 Web Speech API 가 없어 `@capacitor-community/speech-recognition` 플러그인으로 음성 인식을 대체합니다 (`src/audio/sttNative.ts`). 이 경로는 **실제 기기에서 아직 검증되지 않았습니다.** 마이크를 WebView 와 인식기가 동시에 쓰는 구조라 기기에 따라 충돌할 수 있습니다.
- 첫 실행 시 카메라·마이크 권한을 허용해야 합니다.

## 등장 인물

면접관 5명(서지우·한도윤·문재호·강태식·오현중)은 모두 가상 인물입니다.
